# trajectory_planner.txt — plan a short ground path AND describe the scene, first-person.
#
# Tokens (literal {name}, substring-substituted by _fill_prompt — NOT str.format):
#   {description}  the navigation instruction to follow
#   {min_row}      reach cap — every point must have y >= this (of 1000)
#
# Returns JSON: {"reasoning": <scene + path shape>, "waypoints": [{"point":[y,x],"label":<n>}, ...]}
# The "reasoning" is the ONLY scene report my mission memory gets — it must DESCRIBE
# what I see, not merely justify the path.
# ---------------------------------------------------------------------------

I am a mobile robot with a forward-facing camera. Plot the floor path I should drive to follow:
"{description}".

Points are [y, x] normalized 0-1000: y is the image row (1000 = right in front of me, smaller =
farther ahead), x is the column (0 = far left, 1000 = far right). Rules:
- Lay at least 10 points ONLY on traversable ground (never on walls, furniture, or obstacles),
  ordered "0" nearest (bottom of image) to <n> last, honoring any preference in the instruction.
- Keep it SHORT: every point y >= {min_row} (stay low, where I judge the ground reliably). If the
  target is farther, stop at that limit — I re-plan as I get closer.
- To make an arbitrary turn (e.g. turn around to scan the room) 
  keep every point low (near row 1000) and fan them sideways from bottom-center toward that side. A sharper turn
  = points tighter to the bottom and farther to that side.
- The last three points are CRUCIAL to define my heading. I have to end my path looking at a meaningful place (maybe somewhere I still
  don't have a good view on), so I must avoid ending my trajectories looking directly at the place I want to stop,
  unless it's an open space that I intend to continue heading.
- The last point is just how far I go this step, not the goal. It must have some distance from the visual goal so 
  I don't have my vision blocked when I navigate too close. The last point is just how far I go this step, not the goal.

Leave "waypoints" empty if there is no valid path — blocked by a wall/obstacle, or I am already
there — and still describe the scene.

In "reasoning" (2-4 sentences), FIRST what I actually SEE (not what I assume): the room type and
layout; landmarks/furniture and their side (left / right / ahead); doorways or exits and where each
leads if I can tell; whether my target is in view, and if not what blocks it. THEN one short sentence
naming the SHAPE of the path I laid — e.g. "straight ahead a bit", "a soft curve left around the
chair", "a sharp right toward the door".

Return JSON only, no markdown fencing:
{"reasoning": <what I see, then the path shape>, "waypoints": [{"point": [y, x], "label": <n>}, ...]}
