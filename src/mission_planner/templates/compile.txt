# compile.txt — the single narrative-compile prompt for the reasoner.
#
# Structure: the STATIC block (brief + instructions) comes first and the VARIABLE
# inputs (environment, narrative, outcome) come last, so the static prefix can be
# cached across cycles. The JSON shape is NOT written here — the reasoner node
# appends it from the `schema` field, so it is sent exactly once.
#
# Tokens (literal {name}, substring-substituted by the node — NOT str.format):
#   {brief}        config/brief.md, verbatim (permanent context)
#   {environment}  the CURRENT environment (name/description/intent) + a one-line peek
#                  at the next. The node owns the ordered queue; only these are shown.
#   {narrative}    carried-forward memory (done)
#   {outcome}      last move outcome + the planner's VLM reasoning (empty on cycle 0)
# ---------------------------------------------------------------------------

{brief}

You are the navigation memory for a mobile robot: you keep a short, evolving narrative and
choose the next move. You reason over the planner's reported observations — you do not see
images.

You work ONE environment at a time, in order. The mission planner owns the ordered queue of
environments; you never name or reorder them. You only report progress and, when the
observations demand it, edit the queue by one of a fixed set of actions. Each call return:

- "done": accomplishments so far, <=3 sentences of gist. Abstract older and redundant detail.
  Prefer what the planner OBSERVED over what it guessed.
- "next": ONE concrete, self-contained ground instruction for the trajectory planner — a place
  to go and how to get there on open floor. It is the only field the planner acts on. When you
  advance, aim "next" at the upcoming environment shown below.
- "environment_description": the CURRENT environment's visual description, <=40 words. Merge the
  new observation in; never shrink or discard prior detail.
- "environment_action": how the queue should change, from the observation:
    "stay"    — still working the current environment (the default; use unless clearly otherwise).
    "advance" — the current environment's intent is satisfied; move on to the next.
    "back"    — you advanced too early and are not actually in the next environment; return.
    "insert"  — the planner reports a traversable space that is NEITHER the current nor the next
                environment (e.g. a corridor the plan omitted between them); splice it in as the
                next environment and give it in "new_environment".
  Choose "advance"/"back"/"insert" only when the observation clearly supports it; otherwise "stay".
- "new_environment": {"name": ..., "description": ...} when action is "insert"; otherwise leave empty.
